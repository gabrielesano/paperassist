# PaperAssist 0.2.0a1 — Alpha

This alpha completes the native desktop transition and makes external PDF
opening part of the managed library workflow.

- **Native application:** Qt Widgets and PDFium are the default source and
  packaged entry points. The Flask/PDF.js/pywebview stack and Node toolchain have
  been removed. Existing libraries, saved revisions, notes and preferences remain
  compatible.
- **Managed PDF opening:** PDF arguments, Open, Quick view and operating-system
  file events import a copy into the active library. Exact duplicates reuse the
  same paper and latest revision. Explicit Save writes a library revision and
  leaves the external source unchanged. This replaces the previous loose-file
  opening behavior.
- **One owner per library:** repeated launches deliver files to the existing
  window, select open papers and preserve unsaved annotations and comment drafts.
  Different libraries can have separate windows. Delivery uses local sockets or
  named pipes, with no HTTP server.
- **Open with:** Linux desktop integration, an optional Windows setup task and
  macOS Finder support offer PDF opening without replacing the default reader.
- **Included offline OCR:** minimal Tesseract 5.5.4, static Leptonica and the
  English LSTM model recover provisional metadata from scans without a separate
  installation, model download or network connection. OCR does not add a text
  layer to PDFs.

Download the Linux x86_64 installer, Windows x86_64 setup EXE or Apple Silicon
macOS DMG and verify its matching `.sha256` file. Linux release packages target
glibc 2.35 or newer. Platform provenance, OCR manifests, license notices and a
combined checksum manifest are attached alongside the packages. Close the app
before upgrading; uninstalling the application preserves the research library.

The acceptance record is in
[file-opening verification](https://github.com/gabrielesano/paperassist/blob/main/docs/development/file-opening.md).
Use a test library and keep backups. Citation extraction and open-access retrieval
remain partial. Interactive desktop/hardware coverage and clean Ubuntu/Debian GUI
trials remain follow-ups. Windows builds are not Authenticode-signed; macOS builds
are ad-hoc signed, without Developer ID signing or notarization. Intel macOS and
additional architectures are not included.
